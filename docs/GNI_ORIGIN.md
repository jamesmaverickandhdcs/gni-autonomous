# GNI ORIGIN - how GNI got here

**Append-only. Past tense only. Never regenerated.** A record of what happened does not go
stale; a description of the present always does. A line is added at the foot with the
session that wrote it; no line above it is edited or removed. Every session this file cites
must resolve to a record under `docs/` or to a CHAT-ONLY row in the live glossary's SESSION
INDEX, and no commit hash may be cited - the check labelled `origin citations` enforces
both, because the declared history rewrite changes every hash and this file is never
regenerated to follow it.

## THE FIVE STEPS - as James told them at S102, written down at S106

Each step is his account first. What the record adds is marked RECORD and cites the session
that holds it.

**1. BUILT.** GNI's original philosophies, ideas, meanings, vision and mission were built and
operated. That part went fine.

**2. ADDED.** Further thinking was layered on top: measurement and evaluation layers.
RECORD - one of them was the seven-layer security defence. It was designed at the end of
S52, and its layers were built in S52 and S53; neither session left a record under `docs/`,
and both are CHAT-ONLY in the glossary. Until S106 the specification said the defence was
"designed at S53"; the design document carried S53 in its name because S53 was to build it.

**3. CHECKED.** Going back to check whether the added layers were actually operating was
where it stopped being smooth.
RECORD - S69 found a 70-pattern injection detector that nothing had imported since March,
marked DONE, with no debt record. The same session recorded three of the seven declared
defence layers as existing only on paper. The S52 and S53 chats record two of those three as
built. Which account the code supports was not settled at S106; it was passed to the claims
harvest, the row of roadmap 3 that reads the public pages.

**4. THE FLOOR GAVE WAY.** Much later, the check was whether the Web App sub-pages displayed
what the backend actually computed. From that check onward nobody could tell where the
project stood.
RECORD - the sub-page check was named SUBPAGE-IC at S69, given a deliverable at S70, and
re-minted as ROOT 9 at S85. It ran five months with no completion declaration, and no live
document pointed at its deliverable (S92, defect D4 of the architecture document).

**5. WHACK-A-MOLE, UNTIL S92.** The more errors were fixed, the more appeared, and that state
ran until S92.
RECORD - at S92 three questions returned the same answer, that nobody could tell: why a
keyfile task existed, whether SUBPAGE-IC was done, and whether the assistant's own report was
reliable. A full rewrite was proposed and refused, because the code was right; what had
failed was the ability to see it from outside. The direction changed to Smart Office at S92.

## WHAT WAS STILL UNRESOLVED WHEN THIS WAS WRITTEN (S106)

- James could not see how complete GNI was against its founding values and intentions; the
  work had become constant rearranging of the errors that kept surfacing.
- Re-explaining the project to each new session's agent, to bring it up to the previous
  session's understanding, was itself a weakness. This file and the glossary were written at
  S106 so that the next agent could read the account instead of having it re-told.
